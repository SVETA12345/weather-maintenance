# weather-maintenance-api

REST API для планирования технического обслуживания оборудования с учётом погодных условий.
Погодные данные берутся из бесплатного сервиса [Open-Meteo](https://open-meteo.com) (без API-ключа).

## Возможности

- CRUD для оборудования (тип, координаты, критичность, статус).
- Создание и управление заявками на обслуживание.
- Автоматический расчёт приоритета заявки на основе погодной опасности в точке установки оборудования.
- Кэширование погодных данных и ограничение конкурентности запросов к Open-Meteo.
- Структурированные JSON-логи, request-id, централизованная обработка ошибок.
- Готовая Postman-коллекция.

## Требования

- Node.js >= 18.0.0

## Установка и запуск

```bash
npm install
cp .env.example .env   # при необходимости отредактируйте
npm run dev            # режим разработки (auto-restart)
npm start              # продакшен-запуск
```

Сервер по умолчанию поднимется на `http://localhost:3000`.

## Переменные окружения

| Переменная                | По умолчанию                       | Описание                          |
| ------------------------- | ---------------------------------- | --------------------------------- |
| `NODE_ENV`                | `development`                      | Окружение приложения              |
| `PORT`                    | `3000`                             | Порт HTTP-сервера                 |
| `LOG_LEVEL`               | `info`                             | Уровень логирования               |
| `WEATHER_API_URL`         | `https://api.open-meteo.com/v1`    | Базовый URL Open-Meteo            |
| `WEATHER_TIMEOUT_MS`      | `5000`                             | Таймаут запроса к Open-Meteo      |
| `WEATHER_MAX_CONCURRENT`  | `4`                                | Максимум одновременных запросов   |

## API

Все маршруты доступны после префикса `/api` (кроме `/health`).

### Health
| Метод | Путь       | Описание                    |
| ----- | ---------- | --------------------------- |
| GET   | `/health`  | Статус сервиса              |

### Оборудование
| Метод | Путь         | Описание                                   |
| ----- | ------------ | ------------------------------------------ |
| GET   | `/equipment` | Список оборудования (пагинация, фильтры)   |
| GET   | `/equipment/:id` | Получить оборудование                  |
| POST  | `/equipment` | Создать оборудование                       |
| PATCH | `/equipment/:id` | Обновить оборудование                  |
| DELETE| `/equipment/:id` | Удалить оборудование                    |

### Заявки на обслуживание
| Метод | Путь       | Описание                                   |
| ----- | ---------- | ------------------------------------------ |
| GET   | `/requests`| Список заявок (пагинация, фильтры)         |
| GET   | `/requests/:id` | Получить заявку                        |
| POST  | `/requests`| Создать заявку (приоритет рассчитывается из погоды) |
| PATCH | `/requests/:id` | Обновить заявку                        |

### Погода
| Метод | Путь       | Описание                                   |
| ----- | ---------- | ------------------------------------------ |
| GET   | `/weather` | Погода по координатам (`latitude`, `longitude`) |
| GET   | `/weather/equipment/:id` | Погода в точке оборудования       |

Пример создания заявки:

```json
POST /api/requests
{
  "equipmentId": "eq_...",
  "type": "preventive",
  "scheduledDate": "2026-09-25",
  "priority": "high"
}
```

## Структура проекта

```
src/
├── api/weatherClient.js       # клиент Open-Meteo (кэш + ограничение очереди)
├── config/index.js            # конфигурация из env
├── controllers/               # обработчики запросов
├── errors/                    # классы ошибок
├── middlewares/               # request-id, логирование, валидация, ошибки
├── repositories/              # in-memory хранилища
├── routes/                    # маршрутизация
├── services/                  # бизнес-логика
├── validators/                # Joi-схемы
├── utils/                     # id, пагинация, logger
├── app.js                     # сборка Express-приложения
└── server.js                  # запуск сервера
```

## Postman

Импортируйте коллекцию: `docs/postman/collection.json`.
Определите переменную окружения `baseUrl = http://localhost:3000`.

## Логи

Логи выводятся в stdout в JSON-формате. Каждый HTTP-запрос пишется с полями:
`method`, `url`, `status`, `durationMs`, `requestId`.

Для повторения цепочки запросов передавайте заголовок `X-Request-Id`.
